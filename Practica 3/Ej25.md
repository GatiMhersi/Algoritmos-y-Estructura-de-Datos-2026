## Enunciado

Resuelve el **ejercicio 23** (`f 2 3`) utilizando el **orden de reducción lazy (evaluación perezosa)**.

Recordemos las definiciones involucradas:

```haskell
f :: Int -> Int -> Int
f x 0 = x
f x (n + 1) = cuadrado (f x n)

cuadrado :: Int -> Int
cuadrado x = x * x

```

---

## Orden de Reducción Lazy (Evaluación Perezosa)

> **Regla:** Se combina el orden normal (expandir desde afuera hacia adentro) con la **compartición de expresiones** (*sharing*). Un argumento no se evalúa hasta que es estrictamente necesario, y si un valor ya fue calculado, **se memoriza y comparte** para evitar recalcularlo o duplicarlo.

---

## Pasos de Reducción

1. `f 2 3` *(reemplazamos el $3$ por su forma con patrón sucesor $2 + 1$)*
2. `f 2 (2 + 1)`
3. `cuadrado (f 2 2)` *(aplicamos la regla recursiva `f x (n + 1) = cuadrado (f x n)`)*
4. `cuadrado (cuadrado (f 2 1))` *(expandimos nuevamente la función `f`)*
5. `cuadrado (cuadrado (cuadrado (f 2 0)))` *(expandimos por última vez la función `f`)*
6. `cuadrado (cuadrado (cuadrado 2))` *(aplicamos la regla base `f x 0 = x`)*

---

### Evaluación perezosa con Compartición (*Sharing*):

A diferencia del orden normal puro (que duplicaba las expresiones y generaba un árbol enorme de cálculos repetidos), el orden *lazy* evalúa la expresión interna una sola vez y comparte el resultado:

7. Definimos una referencia compartida (un *thunk*) para el valor interno:
* Sea $v = \text{cuadrado } 2$


8. Sustituimos los niveles de cuadrados utilizando ese valor compartido $v$:
* $\text{cuadrado } (\text{cuadrado } v)$


9. Resolvemos el cálculo base de $v$:
* $v = 2 * 2 = 4$


10. Sustituimos $v$ y evaluamos el siguiente nivel de cuadrado:
* $\text{cuadrado } (\text{cuadrado } 4) \implies \text{cuadrado } (4 * 4) = \text{cuadrado } 16$


11. Evaluamos el último nivel de cuadrado externo:
* $16 * 16$


12. **`256`** *(Forma normal alcanzada)*

---

## Comparación y Ventaja del Orden Lazy

* **Eficiencia:** Mientras que el orden normal realizaba múltiples copias redundantes de `cuadrado 2` y recalculaba operaciones, el orden *lazy* evalúa cada subexpresión **exactamente una vez** gracias al mecanismo de *sharing* (memorización).
* **Convergencia:** Llega al mismo resultado correcto (**$256$**) que los otros órdenes de reducción, pero con un costo computacional óptimo.
